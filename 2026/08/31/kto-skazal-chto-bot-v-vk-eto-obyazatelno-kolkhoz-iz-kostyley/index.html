Интеграция Hermes-агента в VK через Long Poll

Большинство ботов в VK до сих пор пишутся по принципу «костыль на синей изоленте». Однако плагин для Hermes меняет подход, превращая сообщество в полноценный интерфейс для AI-агента. Это не примитивный эхо-бот, а полноценный шлюз, который работает с Long Poll API и поддерживает сложную логику взаимодействия.

Технический стек и функционал

Плагин реализует мост между Hermes и VK API, обрабатывая входящие события и отправляя ответы через messages.send.

Ключевые фичи:

  • Работа с контекстом: Поддержка личных сообщений и бесед (корректная обработка peer_id для чатов с префиксом 2000000000).
  • Дедупликация: Встроенный механизм фильтрации событий после реконнекта. Бот не будет спамить одинаковыми ответами, если соединение с сервером VK кратковременно прервалось.
  • Система Allowlist: Гибкое управление доступом через переменную VK_ACCESS_POLICY. Доступны три режима:
    1. user_only — фильтрация по ID пользователя.
    2. peer_only — доступ для конкретных чатов/бесед.
    3. peer_and_user — строгая связка конкретного пользователя в конкретном чате.
  • Обработка медиа: Решена проблема с video.save. Если VK отклоняет сохранение видео, плагин автоматически переотправляет файл как документ, предотвращая silent crash.
  • Форматирование: Поскольку messages.send не поддерживает parse_mode, в плагин встроен конвертер Markdown в plain text.
  • Визуальный фидбек: Реализована имитация статусов (реакции), которые уведомляют пользователя о состоянии агента: обдумывание, успешный ответ или ошибка.

Установка и запуск

Плагин написан с использованием стандартной библиотеки (stdlib), что избавляет от раздутых requirements.txt и конфликтов зависимостей.

# Установка плагина
hermes plugins install vk-gateway

# Настройка шлюза
hermes gateway setup

Субъективная оценка

Почему это круто

Это один из немногих случаев, когда интеграция с VK сделана с учетом реальных проблем API. Дедупликация и автоматический fallback видео в документы экономят часы отладки. Отсутствие внешних зависимостей делает решение максимально легким и стабильным для деплоя на слабые VPS.

Где использовать

  1. Автоматизация поддержки: Создание умного FAQ-бота с доступом к базе знаний через инструменты агента.
  2. Управление сообществами: Модерация и ответы в беседах с разграничением прав доступа.
  3. Cron-уведомления: Использование home-канала для доставки системных алертов или рассылок.

Подводные камни

  1. Токены: Для работы с метаданными видео требуется пользовательский токен. Он имеет ограниченный срок жизни, поэтому придется настроить OAuth-скрипт для его обновления. Режим «поставил и забыл» здесь не работает.
  2. Безопасность: Если оставить VK_ACCESS_POLICY пустым, бот будет отвечать всем. Учитывая, что агент может иметь доступ к системным инструментам (tools), это создает критическую уязвимость. Настройка allowlist обязательна.

Итог

Проект представляет собой качественный опенсорсный инструмент для тех, кому нужен надежный интерфейс к LLM внутри экосистемы VK без написания своего бэкенда с нуля.
