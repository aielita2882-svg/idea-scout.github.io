Автоматизация мониторинга слотов через GitHub Actions и Telegram Mini App

Ручной мониторинг расписания кортов или залов — это пустая трата времени. Вместо того чтобы обновлять страницу каждые пять минут, проще развернуть легковесный скрипт, который будет делать это за вас бесплатно и без собственного сервера.

Рассматриваем кейс трекера свободных слотов, который работает на связке GitHub Actions + Telegram API + Reenio API.

Технический стек и архитектура

Главная фишка проекта — полное отсутствие инфраструктурных затрат. Здесь нет ни VPS, ни внешних баз данных.

  • Runtime: GitHub Actions.
  • Scheduling: Cron-задачи.
  • State Management: Хранение состояния в state.json прямо в репозитории.
  • Frontend для настроек: Telegram Mini App (управление фильтрами без правки конфигов).
  • Уведомления: Telegram Bot API.

Решение проблемы с задержками Cron

Стандартный cron в GitHub Actions может срабатывать с задержками. Чтобы обеспечить интервал проверки в 5–12 минут, реализован bridge-workflow: самоцепляющийся процесс, который запускает проверку и завершает работу только тогда, когда основной нативный cron подхватывает выполнение. Это позволяет добиться максимальной точности мониторинга.

Как это работает внутри

Скрипт взаимодействует с API Reenio, запрашивая текущую занятость площадок. Логика детектирования свободных окон реализована следующим образом:

  1. Сбор данных: Скрипт сканирует доступные 30-минутные слоты.
  2. Фильтрация: Учитывается количество кортов и пересекающиеся брони.
  3. Сравнение состояний: Скрипт сравнивает текущий снимок с данными из state.json. Алерт срабатывает только в случае перехода состояния слота из «занято» в «свободно». Появление новых дат в календаре игнорируется, чтобы избежать спама.
  4. Агрегация: Соседние свободные окна склеиваются в один временной интервал для компактности уведомления.

Практическое применение и настройка

Проект легко адаптируется под любой ресурс, использующий Reenio. Достаточно заменить URL и resource_id в конфигурации.

Процесс деплоя:

  1. Создание бота через BotFather.
  2. Добавление токена в GitHub Secrets.
  3. Настройка фильтров (дни недели и временные интервалы) через Mini App в Telegram.

Для отладки предусмотрен dry-run режим. При запуске локально без токена скрипт выводит в консоль только предполагаемые уведомления, что позволяет проверить логику фильтрации до полноценного запуска в облаке.

Субъективная оценка

Почему это круто:

  • Zero Cost: Использование GitHub Actions как бесплатного планировщика и хостинга для стейта — это элегантный хак.
  • UX: Вынос настроек в Mini App избавляет от необходимости каждый раз делать коммит в репозиторий для смены времени игры.
  • Чистота: Минимум зависимостей и четкая задача.

Подводные камни:

  • Лимиты GitHub: При слишком частом коммите state.json в репозиторий можно столкнуться с замусориванием истории Git (решается использованием отдельной ветки для стейта или очисткой истории).
  • Зависимость от API: Любое изменение в структуре ответов Reenio потребует обновления парсера.

Этот подход универсален. Его можно масштабировать на любой сервис с открытым или полуоткрытым API для мониторинга коворкингов, записи к врачам или отслеживания наличия товаров.
