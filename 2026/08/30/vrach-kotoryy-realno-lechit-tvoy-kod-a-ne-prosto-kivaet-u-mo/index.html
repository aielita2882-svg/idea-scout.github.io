DevEnv Doctor: CLI-инструмент для автоматизации проверки окружения

Развертывание проекта часто превращается в квест по поиску конфликтующих портов, отсутствующих переменных окружения или несовместимых версий Git и Docker. Чтобы не тратить время на ручной дебаг инфраструктуры, существует DevEnv Doctor — CLI-утилита на Python, которая автоматизирует проверку локального окружения.

Что это такое

DevEnv Doctor — это диагностический инструмент, который по одному конфигу проверяет готовность системы к запуску проекта. Вместо того чтобы вручную проверять docker ps или git --version, вы запускаете одну команду и получаете полный отчет о состоянии зависимостей.

Основной функционал

1. Автоматический чеклист

Инструмент проверяет критические точки входа:

  • Версии ПО: Соответствие установленных версий Git, Docker и других утилит требованиям проекта.
  • Сетевые ресурсы: Проверка доступности портов (например, чтобы Postgres не конфликтовал с зависшим процессом).
  • Конфигурация: Наличие и корректность переменных окружения (.env).

2. AI Advisor (GPT-4 Integration)

При установке опционального пакета [ai] в утилиту интегрируется AI-советник на базе GPT-4. Если проверка выявляет ошибку, инструмент не просто выводит stack trace, а предлагает конкретные шаги по исправлению проблемы. Это сокращает время на поиск решения в StackOverflow.

3. Кастомные проверки через YAML

Гибкость настройки обеспечивается через YAML-конфиги. Можно прописать специфические проверки для конкретного стека. Например, проверить, что Redis отвечает PONG на команду PING, прежде чем поднимать приложение.

4. Авто-фикс

Флаг --fix предназначен для автоматического исправления типовых ошибок. На текущем этапе (MVP) реализованы базовые сценарии, но архитектура позволяет расширять список автоматических действий.

Быстрый старт

Установка и запуск занимают меньше минуты:

# Установка базовой версии
pip install devdoctor

# Установка с поддержкой AI
pip install "devdoctor[ai]"

# Инициализация конфига в проекте
devdoctor init

# Запуск полной диагностики
devdoctor check

Технический разбор и субъективная оценка

Почему это полезно: Инструмент решает проблему “it works on my machine”. Добавление devdoctor check в README или в скрипт инициализации проекта (например, в Makefile или package.json) гарантирует, что новый разработчик в команде не застрянет на этапе настройки окружения на полдня.

Где применить:

  • В крупных монорепозиториях с большим количеством зависимостей.
  • В open-source проектах для упрощения онбординга контрибьюторов.
  • В CI/CD пайплайнах для предварительной проверки среды сборки.

Подводные камни: Функционал --fix сейчас находится в состоянии MVP, поэтому полагаться на него в критических системах без присмотра не стоит. Также использование AI-советника требует наличия API-ключа и доступа к сети, что может быть ограничением в закрытых контурах.

Лицензия и развитие

Проект распространяется под лицензией MIT. Это полноценный open-source на Python, который легко форкнуть и доработать под специфические нужды своего стека.

Если вам не хватает конкретных проверок или вы хотите улучшить логику авто-фикса — код открыт для контрибьютов.
