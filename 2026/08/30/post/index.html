Разбор чистого парсера на Python: от HTML до структурированного JSON

Часто студенческие лабораторные по парсингу представляют собой один огромный файл с soup.find_all(), который падает при первой же ошибке 403. Однако попался репозиторий с парсингом каталога бусин Preciosa (biser-optom.ru), который написан по всем канонам разработки: с разделением ответственности, обработкой исключений и нормализацией данных.

Разбираем, почему этот код стоит использовать как референс.

Технический стек и архитектура

Проект реализован на связке Python + BeautifulSoup4. Вместо линейного скрипта автор применил объектно-ориентированный подход, что превращает обычный скрапер в масштабируемый инструмент.

Ключевые инженерные решения:

  1. Кэширование страниц. Скрипт не делает запрос к серверу при каждой итерации отладки. HTML-страницы сначала скачиваются и сохраняются в локальную директорию Saved_pages. Это избавляет от риска получить бан по IP и ускоряет разработку в разы.
  2. Обход защиты. Для запросов используется корректный User-Agent и таймаут в 10 секунд. Без имитации браузера целевой ресурс блокирует запросы, поэтому наличие заголовков здесь — обязательное условие, а не опция.
  3. ООП-модель данных. Весь процесс сбора информации инкапсулирован в класс Card. Вместо того чтобы работать с сырыми словарями, используются методы set_price, set_quantity и export. Это фактически полноценная модель товара из e-commerce системы.
  4. Декораторы для очистки данных. Самая сильная часть кода — использование кастомных декораторов @decorator и @digit. Они решают две главные проблемы парсинга:
    • Обработка None и пустых значений, чтобы скрипт не падал с AttributeError.
    • Конвертация строковых цен (например, “1 500 ₽”) в чистые целые числа (int), пригодные для математических операций.

Результат: Структурированный датасет

На выходе получается JSON-файл с 500+ товарами. Каждый объект содержит 14 полей: id, code, type, size, color, price, old_price, currency, sale, weight, quantity, image, url.

Такой формат данных позволяет мгновенно импортировать их в Pandas для анализа или в любую SQL-базу для создания собственного каталога.

Практическое применение и оценка

Этот подход легко масштабируется на любой интернет-магазин или маркетплейс. Имея такой пайплайн, можно реализовать:

  • Мониторинг цен конкурентов: автоматический трекинг изменений price и old_price.
  • Анализ скидок: расчет реального процента скидки через поле sale.
  • Контроль остатков: отслеживание quantity для анализа спроса.

Вердикт: Код крут тем, что в нем нет «мусорных» решений. Автор не просто вытащил текст со страницы, а создал конвейер по превращению неструктурированного HTML в чистые данные.

Подводные камни: Единственный минус — зависимость от структуры HTML. При любом редизайне сайта селекторы в BeautifulSoup придется переписывать. Для более крупных проектов в будущем стоило бы добавить поддержку прокси и асинхронность через httpx или aiohttp, чтобы ускорить сбор данных с тысяч страниц.

Для тех, кто изучает веб-скрапинг: используйте этот репозиторий как пример того, как структурировать код, чтобы он не превратился в спагетти.
