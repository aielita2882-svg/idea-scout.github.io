# Как я перестал обновлять страницу сайта и начал жить: автоматический трекер свободных кортов

Каждое утро одно и то же: открываешь сайт спорткомплекса, листаешь расписание, обновляешь — занято, обновляешь — занято, обновляешь — бац, кто-то отменил бронь за те 30 секунд, пока ты моргнул. Знакомо? Знакомо.

Решение этой проблемы — **Court Radar** — бот, который мониторит расписание и присылает уведомление ровно в тот момент, когда появляется свободное окошко. Без VPS, без базы данных, без головной боли.

## Как это работает

Скрипт стучится к API системы бронирования (в данном случае Reenio), забирает текущее расписание и сравнивает с предыдущим снимком. Если слот был в нуле, а теперь свободен — шлёт алерт в Telegram. Всё.

**Ключевые компоненты:**

- **GitHub Actions** — крутит скрипт по cron. Никаких серверов, бесплатно, на чужих мощностях.
- **state.json** — хранит предыдущее состояние прямо в репозитории. Просто, эффективно, не нужно поднимать Redis.
- **Bridge-воркфлоу** — умный костыль для быстрого старта. GitHub Actions имеет ограничение: первый запуск после деплоя может занять до часа. Bridge проверяет каждые 5 минут и глушит себя, когда основной cron подхватит работу.

## Настройка за 10 минут

Процесс элементарный:

1. Создаёшь бота через **BotFather** — получаешь токен.
2. Закидываешь токен в **GitHub Secrets**.
3. Пишешь боту `/start`.
4. Открываешь Mini App с фильтрами — выбираешь дни недели и часы.
5. PROFIT.

Никакого ручного редактирования YAML-конфигов. Всё через интерфейс Telegram.

## Что внутри

**Детект освобождений** сделан грамотно:

- Считаются свободные 30-минутные слоты
- Учитываются пересекающиеся брони (например, три корта на площадке)
- Соседние окна склеиваются в один интервал — чтобы не спамить 4 раза подряд
- Новая дата на горизонте **не** считается событием — только реальные отмены

**Dry-run режим** — запускаешь локально без токена, скрипт просто пишет в консоль, что отправил бы. Удобно для отладки логики перед подключением бота.

## Почему это круто

Подход **универсальный**. Проект заточен под конкретный спорткомплекс и API Reenio, но архитектура — это просто шаблон. Меняешь URL и resource_id — получаешь трекер любого места: зал, коворкинг, бассейн, что угодно.

GitHub Actions как планировщик — это вообще недооценённый паттерн. Бесплатные 2000 минут в месяц для периодических задач — более чем достаточно. state.json в репозитории — не идеально для highload, но для персональных проектов просто и надёжно.

**Bridge-воркфлоу** — это инженерное мышление в чистом виде. Проблема: cron не гарантирует запуск вовремя. Решение: дополнительный воркфлоу, который страхует и самоуничтожается. Элегантно.

## Где применить

Идеальный сценарий:

- Популярные площадки с дефицитом слотов
- Бронирование переговорок в офисе
- Отслеживание мест в курсах или секциях
- Любая система с ограниченным ресурсом и веб-API
