Вы когда-нибудь мечтали о парсере, который не надо переписывать под каждый сайт заново? Я — да. И знаете что? Похоже, я нашла кое-что интересное
🔥
Представляю VekParser — это не просто очередной скрапер, а целая архитектура для сбора данных с веб-сайтов. Вся логика описывается в YAML-конфигурации, а Python-код пишется только под кастомные шаги. То есть парсинг без боли и копипасты.
Что меня зацепило конкретно:
⚡
Многоступенчатая обработка данных через YAML-конфигурацию — настроил шаги static, extract, list, save, и оно само крутится
⚡
Поддержка параллельного выполнения задач — max_workers регулируется, так что можно ускорить сбор в разы
⚡
Встроенная работа с динамическим контентом через Playwright — для тех SPA, где контент рендерится JavaScriptом
⚡
Кастомные обработчики — регистрируешь свой тип шага и вперёд
⚡
Автоматическое сохранение результатов в JSON — ничего не потеряется
Жизненный цикл данных выглядит логично: инициализация контекста через static, извлечение через extract с CSS/XPath селекторами, параллельная обработка списка через list, финализация через save. Всё прозрачно, никакой магии.
А ещё тут есть приятные мелочи для тех, кто пишет на Python: уровни логирования от DEBUG до ERROR, настраиваемый интервал запросов через HttpClient и тот самый JS-рендеринг для тяжёлых случаев. В общем, для проектов по сбору данных с сайтов — штука стоящая
🎯
Я попробовала разобраться в структуре конфигурации — и знаете, ощущение, будто кто-то наконец сел и нормально продумал расширяемость. Кастомные обработчики регистрируются в пару строк, обработчики элементов списка поддерживают string, link, dict, и можно добавлять свои. Плюс механизм сохранения с явным указанием fields — никаких сюрпризов в JSON на выходе.
Мой вердикт: если вы устали писать BeautifulSoup-портянки под каждый новый сайт — посмотрите внимательно. Это не серебряная пуля, но очень достойный фреймворк для парсинга веб-сайтов на Python, который растёт вместе с вашими задачами
💡
