# VekParser: Декларативный подход к веб-скрапингу на Python

Если ваш типичный рабочий день состоит из написания бесконечных цепочек `BeautifulSoup` и переписывания селекторов под каждый новый чих фронтенд-разработчиков, пора менять стек. Большинство скраперов страдают от жесткой привязки логики к коду. **VekParser** решает эту проблему, вынося описание процесса сбора данных в YAML-конфигурации.

По сути, это фреймворк, который превращает парсинг из написания скриптов в проектирование конвейеров обработки данных.

## Технический стек и архитектура

VekParser реализует многоступенчатый пайплайн. Вместо того чтобы описывать каждый шаг в Python-коде, вы создаете YAML-файл, где определяете жизненный цикл данных:

1. **static**: Инициализация контекста и базовых параметров.
2. **extract**: Извлечение данных с помощью CSS или XPath селекторов.
3. **list**: Параллельная обработка списков элементов.
4. **save**: Финализация и экспорт данных в JSON.

### Ключевые фичи

* **JS-рендеринг через Playwright**: Встроенная поддержка динамического контента. Если сайт представляет собой SPA или данные подгружаются через JS, VekParser задействует браузерный движок, избавляя от необходимости вручную реверсить API сайта.
* **Параллелизм**: Параметр `max_workers` позволяет масштабировать сбор данных, эффективно используя многопоточность.
* **Кастомные обработчики**: Если стандартных типов (`string`, `link`, `dict`) недостаточно, можно зарегистрировать собственный тип шага в Python и вызвать его из YAML-конфига.
* **Контроль трафика**: Настраиваемый `HttpClient` с регулируемыми интервалами запросов помогает минимизировать риск получения 429 Too Many Requests.
* **Логирование**: Полноценная поддержка уровней от `DEBUG` до `ERROR`, что критично при отладке сложных селекторов на больших объемах данных.

## Практическое применение

Этот инструмент идеально вписывается в проекты, где нужно собирать данные с десятков однотипных или слегка различающихся ресурсов. Вместо создания 20 разных `.py` файлов, вы создаете 20 YAML-конфигов и один общий движок запуска.

**Пример сценария:**
Сбор каталога товаров $\rightarrow$ Переход по каждой ссылке товара (параллельно) $\rightarrow$ Извлечение характеристик $\rightarrow$ Сохранение в структурированный JSON с четко заданными `fields`.

## Субъективная оценка

**Почему это круто:**
Главный профит — разделение ответственности. Разработчик пишет расширения (кастомные обработчики), а аналитик или менее опытный кодер может настраивать парсинг новых страниц, просто правя YAML-файл. Это на порядок ускоряет итерации.

**Подводные камни:**
Как и любой декларативный подход, YAML-конфиги могут стать громоздкими при реализации слишком сложной бизнес-логики (например, сложной системы обхода капчи или многоуровневой авторизации с динамическими токенами). В таких случаях придется писать больше кастомного Python-кода, что частично нивелирует идею "конфиг вместо кода".

**Вердикт:**
VekParser — это не "серебряная пуля", но мощный инструмент для тех, кто перерос простые скрипты и хочет построить расширяемую систему сбора данных. Если вам нужен порядок в архитектуре скрапера и поддержка современного веба (SPA), этот фреймворк однозначно стоит попробовать.

Проект полностью Open Source.
