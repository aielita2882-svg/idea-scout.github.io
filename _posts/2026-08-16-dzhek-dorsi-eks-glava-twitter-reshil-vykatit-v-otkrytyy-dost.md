# Джек Дорси выложил в open-source фреймворк для управления AI-агентами в бизнес-процессах

Джек Дорси, бывший CEO Twitter, продолжает удивлять. На этот раз он выпустил в открытый доступ исходный код фреймворка, который позволяет интегрировать AI-агентов прямо в рабочие каналы команды. Агенты ведут себя как полноценные участники: получают задачи, отчитываются о выполнении, взаимодействуют с коллегами.

## Что это и зачем нужно

По сути, это middleware-слой между вашими бизнес-процессами и AI-моделями. Фреймворк берёт на себя рутину: управляет каналами коммуникации, поисковыми запросами, интеграцией с Git и всевозможными автоматизациями. Вы описываете процесс — фреймворк обеспечивает выполнение.

**Ключевые фичи:**

- Подключение агентов к каналам (Slack-подобные, внутренние мессенджеры)
- Настройка прав доступа для каждого агента
- Работа в режиме реального времени
- Интеграция с Git (коммиты, пул-реквесты, ревью)
- Поиск по документации и базам знаний
- Кастомные автоматизации через API

## Как это работает: быстрый старт

Схема элементарная:

1. **Клонируете репозиторий** с GitHub
2. **Поднимаете свой сервер** — это может быть VPS, облако или локальная машина
3. **Конфигурируете каналы** — указываете, с какими сервисами работать
4. **Добавляете агента** в нужный канал как участника
5. **Раздаёте права** — что агент может читать, писать, выполнять
6. **Работаете** — общаетесь с агентом в привычном интерфейсе

```bash
git clone https://github.com/jackdorsey/agent-framework.git
cd agent-framework
docker-compose up -d
```

После запуска сервер готов принимать запросы. Конфиг задаётся через YAML или через UI.

## Архитектура: что под капотом

Фреймворк построен на нескольких слоях:

- **Communication Layer** — адаптеры для каналов (Slack, Discord, Mattermost, свой WebSocket)
- **Agent Core** — ядро с плагинной системой для подключения разных AI-провайдеров
- **Process Engine** — движок бизнес-логики, очереди задач, стейт-машины
- **Integration Bus** — шина для связи с внешними сервисами (Git, Jira, Notion, базы данных)

Агенты могут быть специализированными: один занимается код-ревью, другой — поиском информации, третий — генерацией отчётов. Или можно сделать одного универсального — зависит от задачи.

## Практическое применение

Вот где это реально пригождается:

**DevOps-команды.** Агент мониторит CI/CD, реагирует на фейлы билдов, предлагает исправления и даже может открывать пул-реквесты с фиксами.

**Поддержка.** Агент в канале тикет-системы отвечает на типовые вопросы, собирает логи, эскалирует сложные случаи людям.

**Онбординг.** Новый сотрудник общается с агентом, который отвечает на вопросы по процессам, даёт ссылки на документацию, направляет к нужным людям.

**Аналитика.** Агент строит отчёты по запросу, достаёт данные из баз, визуализирует метрики.

## Почему это круто

Дорся сделал то, что многие пытаются продать за деньги — полноценный фреймворк для human-in-the-loop автоматизации. Агенты не заменяют людей, а встраиваются в существующие процессы. Это важно, потому что:

- Не нужно менять привычный рабочий процесс
- Контроль остаётся у людей
- Агент — это ещё один участник команды, а не отдельная сущность

С точки зрения реализации — код чистый, документация вменяемая, архитектура расширяемая. Можно форкнуть и допилить под себя без боли.

## Что стоит учитывать

Как всегда с open-source от экс-CEO Twitter — это early-stage проект. Из коробки может не работать всё гладко, потребуется время на настройку. Но если вам нужен свой фреймворк для AI-агентов в бизнесе — хорошая точка входа.
