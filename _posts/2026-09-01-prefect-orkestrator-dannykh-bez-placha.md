# Prefect — оркестратор данных без слёз

## Что это и зачем

Prefect — это Python-фреймворк для оркестровки рабочих процессов. Если коротко: вы описываете логику пайплайна, а Prefect берёт на себя планирование, повторные запуски при сбоях и мониторинг выполнения.

Забудьте про bash-скрипты с cron. Забудьте про "а давайте добавим ещё один костыль". Вместо этого вы получаете декларативное описание DAG с автоматическим управлением зависимостями и встроенным UI для отладки.

## Ключевые фичи

**Модель задач** — это не просто обёртка над функциями. Tasks в Prefect поддерживают:

- асинхронное выполнение (async/await из коробки)
- retries с настраиваемой логикой — можно задать количество попыток, задержку, условия для повтора
- timeouts на каждый шаг
- кэширование результатов между запусками

**UI в реальном времени** — визуализация графа задач, живые логи, метрики выполнения. Можно понять, где именно застрял пайплайн, не ныряя в терминал.

**Гибкость деплоя** — локальный запуск для разработки, Prefect Cloud для прода, свой Kubernetes-кластер для параноиков. Переключение между окружениями — одна строка в конфиге.

**Интеграции** — подключаетесь к Snowflake, BigQuery, Postgres, Dask, Docker, Kubernetes. Отправляете уведомления в Slack или Discord. Prefects понимает, что данные могут прийти кривыми, и сообщает об этом куда нужно.

## Кому это надо

**Инженерам данных**, которые устали поддерживать скрипты, которые "почти работают". Если вы вручную перезапускаете ETL в пятницу вечером — это сигнал.

**ML-инженерам** — тренировка модели, валидация, инференс, мониторинг дрифта. Всё в одном пайплайне с контролем версий и воспроизводимостью.

**Тем, кто готовится к собеседованиям** — понимание workflow orchestration показывает, что вы мыслите системно, а не лепите всё в один скрипт.

## Как выглядит код

```python
from prefect import flow, task

@task(retries=3, retry_delay_seconds=60)
def extract():
    return [1, 2, 3, 4, 5]

@task
def transform(data):
    return [x * 2 for x in data]

@flow
def etl_pipeline():
    raw = extract()
    processed = transform(raw)
    return processed
```

Запускаете локально — работает. Переключаетесь на Cloud — получаете историю запусков, логи, уведомления. Всё.

## Моё мнение

Prefect выигрывает у Airflow там, где важна простота и гибкость. Airflow — это тяжёлая артиллерия с кучей конфигов. Prefect — это когда вы хотите написать пайплайн быстро и не думать про инфраструктуру.

Минусы? Prefect Cloud бесплатный тариф ограничен — для серьёзных проектов придётся платить. Но для обучения и небольших продакшен-систем хватает за глаза.

**GitHub**: 23k+ звёзд, активная разработка, Python-first. Если вы уже пишете на Python и вам нужен оркестратор — начните с Prefect. Это тот случай, когда инструмент не пытается быть сложнее, чем нужно.
