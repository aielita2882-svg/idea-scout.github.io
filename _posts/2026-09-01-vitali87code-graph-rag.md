# code-graph-rag: RAG для монorepo, который реально понимает ваш код

Вместо вступления — боль. Каждый разработчик знает это чувство, когда тебя бросают в огромный монorepo с десятью языками программирования и говорят: "разберись". Ты открываешь IDE, пытаешься найти нужную функцию через grep, ищешь по ключевым словам, открываешь десятки файлов в случайном порядке...

Знакомо? Так вот, есть инструмент, который превращает этот ад в нечто управляемое.

## Что это и зачем

**code-graph-rag** — это RAG-система, заточенная под монorepo. Она не просто индексирует код как плоский текст, а строит поверх него **knowledge graph**: знает, какие модули связаны, кто кого импортирует, какие функции вызывают друг друга. Плюс AI-слой поверх графа, который позволяет не только искать, но и получать контекстные ответы с пониманием всей архитектуры проекта.

По сути — умный навигатор по кодовой базе, который понимает структуру, а не просто парсит строки.

## Фичи, которые реально нужны

**Мультиязычная поддержка.** Не надо писать отдельные парсеры для Python, Go, TypeScript и всего остального зоопарка в вашем репозитории. Система понимает их все из коробки.

**Knowledge graph.** Связи между классами, функциями и модулями хранятся как граф, а не как простыня текста. Это позволяет отвечать на вопросы уровня "как эта функция связана с бизнес-логикой" — а не только "найди слово X".

**AI-powered редактирование.** Можно не только спрашивать "где используется эта функция", но и попросить внести изменения с учетом всего контекста. Система понимает, что трогать, а что лучше не трогать.

**Векторный поиск + семантика.** Находит релевантный код, даже когда вы не помните точное название класса. Описываете задачу своими словами — получаете нужные файлы.

## Кому это надо

**Команды с большими монorepo.** Когда у вас десятки разработчиков и кодовая база на несколько языков — это буквально необходимость. Вместо того чтобы тратить часы на поиск связей, спрашиваете граф и получаете ответ за секунды.

**Онбординг новичков.** Вместо двухнедельного погружения в кодовую базу новый разработчик может просто спросить у системы, как устроен проект. "Покажи архитектуру модуля авторизации" — и через минуту у тебя есть полная картина.

**Фрилансеры и консультанты.** Вам скинули легаси-проект и сказали "разберись"? Это ваше спасение. Без такого инструмента можно медитировать над спагетти-кодом месяцами. С ним — хотя бы понять структуру за приемлемое время.

## Как это работает (практика)

Установка:

```bash
pip install code-graph-rag
```

Индексация проекта:

```bash
code-graph-rag index ./my-monorepo
```

Запросы:

```bash
# Найти все места использования функции
code-graph-rag query "Where is get_user_data used?"

# Понять структуру модуля
code-graph-rag query "Explain the payment module architecture"

# Найти код по описанию
code-graph-rag query "Find code that handles image compression"
```

Система анализирует граф зависимостей и выдает структурированный ответ с учетом всех связей. Не просто список файлов, а полноценный контекст.

## Почему это круто (субъективно)

Я видел много инструментов для навигации по коду. Большинство — это продвинутый grep с веб-интерфейсом. code-graph-rag делает шаг вперед: **графовая модель данных**.

Когда вы ищете что-то в обычном инструменте, вы получаете список файлов. Когда вы ищете в code-graph-rag, вы получаете **понимание** — как компоненты связаны, какие зависимости есть, где потенциальные проблемы.

Это не магия, это правильная архитектура. Векторный поиск ловит семантическую релевантность, граф хранит структурные связи, AI объединяет всё в читаемый ответ.

**Вердикт:** если у вас монorepo больше пары десятков тысяч строк — попробуйте. Экономия времени на навигации по коду окупает затраты на интеграцию за первую неделю.
